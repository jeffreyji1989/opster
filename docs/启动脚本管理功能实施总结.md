# 启动脚本管理功能实施总结

## 实施日期
2026-03-15

## 功能概述
实现了一个启动脚本管理模块，支持脚本的创建、编辑、版本控制、以及部署时自动上传脚本到服务器。

**注意**: 根据用户需求调整，启动脚本管理功能不独立设菜单，而是集成到服务管理页面的"更多"操作下拉菜单中，与配置文件管理功能保持一致的交互模式。

## 需求回顾
1. **独立管理脚本** - 不在服务编辑中生成，作为服务管理的一个子功能
2. **支持新增、编辑** - 可以创建多个脚本模板（已实现在启动脚本管理对话框中）
3. **历史版本管理** - 每次修改保留版本记录
4. **标准脚本模板** - 新增时生成标准脚本
5. **自动完善脚本** - 通过编辑 JVM 参数、前后命令字段自动生成脚本内容
6. **发版时上传** - 部署服务时，将选中的脚本版本一起上传到服务器

## 实施内容

### 1. 数据库设计

#### 1.1 启动脚本主表 (service_start_script)
```sql
CREATE TABLE service_start_script (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name VARCHAR(100) NOT NULL,           -- 脚本名称
    description VARCHAR(500),              -- 脚本描述
    port INTEGER NOT NULL,                 -- 服务端口
    jvm_args VARCHAR(1000),                -- JVM 参数
    pre_java_cmd VARCHAR(1000),            -- Java 命令前的命令
    post_java_cmd VARCHAR(1000),           -- Java 命令后的命令
    current_version_id INTEGER,            -- 当前生效的版本 ID
    is_default INTEGER DEFAULT 0,          -- 是否为默认脚本
    del_flag INTEGER DEFAULT 0,            -- 删除标志
    create_by INTEGER,                     -- 创建人 ID
    create_time DATETIME,                  -- 创建时间
    update_by INTEGER,                     -- 更新人 ID
    update_time DATETIME                   -- 更新时间
);
```

#### 1.2 启动脚本版本表 (service_start_script_version)
```sql
CREATE TABLE service_start_script_version (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    script_id INTEGER NOT NULL,            -- 关联脚本 ID
    version_no VARCHAR(20) NOT NULL,       -- 版本号 (如：v1.0.0)
    version_description VARCHAR(500),      -- 版本描述
    port INTEGER NOT NULL,                 -- 服务端口
    jvm_args VARCHAR(1000),                -- JVM 参数
    pre_java_cmd VARCHAR(1000),            -- Java 命令前的命令
    post_java_cmd VARCHAR(1000),           -- Java 命令后的命令
    script_content TEXT NOT NULL,          -- 生成的完整脚本内容
    is_active INTEGER DEFAULT 0,           -- 是否为激活版本
    del_flag INTEGER DEFAULT 0,            -- 删除标志
    create_by INTEGER,                     -- 创建人 ID
    create_time DATETIME,                  -- 创建时间
    update_by INTEGER,                     -- 更新人 ID
    update_time DATETIME                   -- 更新时间
);
```

#### 1.3 服务表变更 (service)
新增字段：

- `start_script_version_id` - 关联的启动脚本版本 ID

### 4. 核心功能实现

#### 4.1 标准脚本模板生成
通过 `ScriptTemplateBuilder` 类生成标准化的 Spring Boot 启动脚本，包含：
- 配置区（端口、JVM 参数、前后命令）
- 颜色定义（日志输出美化）
- 日志函数（统一日志格式）
- Java 环境检查
- 端口占用检查与清理
- 前置命令执行
- Java 应用启动
- 后置命令执行
- 健康检查

#### 4.2 版本控制逻辑
- 创建脚本时自动生成 v1.0.0 版本
- 更新脚本时自动递增版本号（v1.0.1, v1.0.2...）
- 每次更新创建新版本并保留历史记录
- 支持激活历史版本（版本回退）

#### 4.3 部署时脚本上传
在 `DeploymentOrchestrationServiceImpl` 中添加：
- `uploadStartScript()` - 上传启动脚本到远程服务器
- `executeRemoteCommandWithoutLogging()` - 执行无日志输出的命令

部署流程：
1. 停止旧服务
2. 上传启动脚本（如果服务关联了脚本版本）
3. 设置脚本执行权限
4. 执行启动脚本

## 使用流程

### 创建启动脚本
1. 进入"启动脚本管理"页面
2. 点击"新增脚本"
3. 填写脚本名称、描述、端口、JVM 参数、前后命令
4. 可选择是否设为默认脚本
5. 保存后自动生成标准脚本

### 编辑脚本
1. 点击"编辑"按钮
2. 修改配置字段
3. 保存后自动创建新版本（版本号自动递增）
4. 新版本自动激活

### 版本管理
1. 点击"版本"按钮查看历史版本
2. 可激活历史版本（版本回退）
3. 可查看每个版本的脚本内容

### 部署时使用
1. 在服务管理中关联启动脚本
2. 发版时自动上传脚本到服务器
3. 通过脚本启动服务

## 脚本模板示例

```bash
#!/bin/bash
# ============================================================
# Spring Boot 应用启动脚本
# 自动生成于 Opster 平台
# ============================================================
# 脚本名称：标准 Spring Boot 启动脚本
# 版本号：v1.0.0
# 服务端口：8080
# ============================================================

# ========== 配置区 ==========
PORT="8080"
JVM_ARGS="-Xms256m -Xmx512m -Dspring.profiles.active=dev"
PRE_JAVA_CMD="fuser -k 8080/tcp"
POST_JAVA_CMD="curl http://localhost:8080/health"
JAR_NAME="*.jar"
LOG_DIR="logs"
PID_FILE="app.pid"
STARTUP_WAIT_TIME=30

# ========== 颜色定义 ==========
RED='\033[0;31m'
GREEN='\033[0;32m'
YELLOW='\033[1;33m'
BLUE='\033[0;34m'
NC='\033[0m'

# ========== 日志函数 ==========
log_info() { echo -e "${GREEN}[$(date '+%Y-%m-%d %H:%M:%S')] INFO: $1${NC}"; }
log_error() { echo -e "${RED}[$(date '+%Y-%m-%d %H:%M:%S')] ERROR: $1${NC}"; }
log_warn() { echo -e "${YELLOW}[$(date '+%Y-%m-%d %H:%M:%S')] WARN: $1${NC}"; }
log_step() { echo -e "${BLUE}[$(date '+%Y-%m-%d %H:%M:%S')] STEP: $1${NC}"; }

# ========== 检查 Java 环境 ==========
check_java() {
    log_step "检查 Java 环境..."
    if [ -n "$JAVA_HOME" ] && [ -x "$JAVA_HOME/bin/java" ]; then
        export PATH="$JAVA_HOME/bin:$PATH"
        log_info "使用 JAVA_HOME: $JAVA_HOME"
        return 0
    fi
    if command -v java &> /dev/null; then
        log_info "使用系统 Java: $(java -version 2>&1 | head -1)"
        return 0
    fi
    log_error "Java 未安装，请设置 JAVA_HOME"
    exit 1
}

# ========== 检查并清理端口 ==========
check_and_kill_port() {
    log_step "检查端口 $PORT 占用情况..."
    local pid=$(lsof -ti:$PORT 2>/dev/null)
    if [ -n "$pid" ]; then
        log_warn "端口 $PORT 被占用 (PID: $pid)"
        if ps -p "$pid" -o command= 2>/dev/null | grep -q "java"; then
            log_info "尝试优雅停止 Java 进程..."
            kill "$pid" 2>/dev/null && sleep 2 && kill -9 "$pid" 2>/dev/null || true
            sleep 1
        else
            log_error "端口被非 Java 进程占用，请手动处理"
            exit 1
        fi
        if lsof -ti:$PORT > /dev/null 2>&1; then
            log_error "端口仍未释放"
            exit 1
        fi
        log_info "端口 $PORT 已释放"
    fi
}

# ========== 执行前置命令 ==========
execute_pre_java_cmd() {
    if [ -n "$PRE_JAVA_CMD" ]; then
        log_step "执行启动前命令：$PRE_JAVA_CMD"
        eval "$PRE_JAVA_CMD" 2>&1 || log_warn "前置命令执行失败，继续启动"
    fi
}

# ========== 启动 Java 应用 ==========
start_java_app() {
    log_step "启动 Java 应用..."
    local jar_file=$(ls -1 $JAR_NAME 2>/dev/null | head -1)
    if [ -z "$jar_file" ]; then
        log_error "未找到 jar 文件"
        exit 1
    fi
    log_info "找到 jar 文件：$jar_file"

    mkdir -p "$LOG_DIR"
    local java_cmd="java $JVM_ARGS -jar $jar_file"
    log_info "启动命令：$java_cmd"

    nohup $java_cmd > "$LOG_DIR/startup.log" 2>&1 &
    local app_pid=$!
    echo $app_pid > "$PID_FILE"
    log_info "服务已启动 (PID: $app_pid)"

    log_step "等待服务启动（最多 ${STARTUP_WAIT_TIME} 秒）..."
    local waited=0
    while [ $waited -lt $STARTUP_WAIT_TIME ]; do
        if ! ps -p "$app_pid" > /dev/null 2>&1; then
            log_error "服务进程已退出"
            exit 1
        fi
        if lsof -ti:$PORT > /dev/null 2>&1; then
            log_info "端口 $PORT 开始监听"
            break
        fi
        sleep 1
        waited=$((waited + 1))
    done
}

# ========== 执行后置命令 ==========
execute_post_java_cmd() {
    if [ -n "$POST_JAVA_CMD" ]; then
        log_step "执行启动后命令：$POST_JAVA_CMD"
        eval "$POST_JAVA_CMD" 2>&1 || log_warn "后置命令执行失败"
    fi
}

# ========== 主流程 ==========
main() {
    log_info "========================================"
    log_info "启动 Spring Boot 服务"
    log_info "端口：$PORT"
    log_info "========================================"
    check_java
    check_and_kill_port
    execute_pre_java_cmd
    start_java_app
    execute_post_java_cmd
    log_info "========================================"
    log_info "服务启动完成"
    log_info "========================================"
}

main
```
