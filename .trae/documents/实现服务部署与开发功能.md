我将为您实现“部署并开发”功能。由于这是一个涉及远程服务器操作的复杂任务，我们需要引入 SSH 客户端库（JSch）并实现详细的步骤逻辑。

## 1. 依赖管理
- **pom.xml**: 添加 `jsch` 依赖，用于执行 SSH 命令和 SCP 文件传输。

## 2. 工具类封装
- **创建 `SshUtils` 工具类**:
    - `Session connect(String host, int port, String user, String password)`: 建立 SSH 连接。
    - `String exec(Session session, String command)`: 执行远程 Shell 命令并获取输出。
    - `void scpUpload(Session session, String localFile, String remoteDir)`: 上传文件到远程服务器。

## 3. 核心业务逻辑实现
- **修改 `AppServiceServiceImpl`**: 实现 `compileAndRestart` 方法的真实逻辑。
    - **Step 1**: 根据 `serverId` 查询服务器信息（IP, 用户名, 密码）。
    - **Step 2**: 建立 SSH 连接。
    - **Step 3 & 4 (Git & Maven)**: 
        - 拼接组合命令：`cd [deployPath] && git clone [gitUrl] source || (cd source && git pull) && cd source && mvn clean package`
        - 注意：如果 source 目录已存在，则执行 git pull；否则执行 git clone。
        - 执行 Maven 构建命令。
    - **Step 5 (Copy Jar)**: 
        - 找到构建出的 JAR 包（通常在 `source/target/*.jar`）。
        - 将 JAR 包移动/拷贝到部署目录 `[deployPath]`。
        - *注意*: 原需求提到“拷贝到服务器设置的部署目录”，如果构建过程是在服务器上进行的（正如步骤3-4所述），则直接使用 `cp` 命令即可，不需要 SCP 上传。如果是在本地构建再上传，逻辑会有所不同。**根据您的描述，步骤3-4是在“当前目录”（即服务器部署目录）下进行的，因此全流程都在服务器端执行，无需本地构建和上传。**
    - **Step 6 (Restart)**: 执行启动脚本 `sh [startScript]`。
    - **Step 7**: 收集并返回执行日志。

## 4. 接口调整
- 确保 `ServiceController` 的 `compileAndRestart` 接口能够正确调用并返回详细日志。

## 5. 验证
- 编写单元测试或集成测试来验证逻辑（由于涉及真实 SSH，可能需要 Mock 或手动验证）。

*确认事项*: 您的需求中步骤3-5描述的是在“当前目录”操作，我理解为**所有操作（Git clone, Maven build, Copy, Start）都在远程服务器上执行**，而不是在运行 Opster 后端的本地机器上执行。这样的设计要求远程服务器必须安装 Git 和 Maven。我将按照这个逻辑实现。
