我已完成启动和重启逻辑的 WebSocket 实时化改造。

## 1. 后端 (ExecWebSocketHandler)
- **新组件**: 创建了 `ExecWebSocketHandler`，专门处理 `/ws/exec/{serviceId}/{action}` 的 WebSocket 连接。
- **逻辑迁移**: 将原 `AppServiceServiceImpl` 中的 `compileAndRestart`、`restart`、`start` 的核心 SSH 执行逻辑（包括 Git 更新、Maven 构建、Jar 包复制、启动脚本执行、端口检测）全部迁移到了 WebSocket Handler 中。
- **实时反馈**: 所有的 SSH 命令输出（stdout/stderr）现在都会通过 `wsSession.sendMessage` 实时推送给前端，不再是执行完才一次性返回。
- **资源管理**: 连接建立时创建 SSH Session，连接关闭（执行结束或前端主动关闭）时自动释放 SSH 资源。

## 2. 前端 (Service.vue)
- **handleAction**: 不再使用 `axios.post` 发送 HTTP 请求。
- **WebSocket 交互**: 点击确认后，立即打开“执行结果”弹窗，并建立 WebSocket 连接。
- **实时展示**: 接收后端推送的实时日志流，并自动滚动展示在弹窗中。
- **状态同步**: 执行完成后（WebSocket 断开），自动刷新列表数据以更新服务状态（正常/异常）。

## 3. 验证步骤
1. **重启后端**: `mvn spring-boot:run`
2. **执行操作**: 在前端点击“编译并重启”或“重启”。
3. **观察效果**: 弹窗会立即出现，并逐行显示正在执行的命令输出（如 Git Pull 进度、Maven 构建日志、启动脚本输出等），而不是一直转圈等待。
